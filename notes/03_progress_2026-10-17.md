## Perl ↔ Python parity (`regression/run_regression.sh`)
Five sample datasets were compared (Trinity, PASA, StringTie -S, SuperTranscripts, Cufflinks). Both implementations ran with default settings and no homology evidence.

**After the fixes (`data/regression/dev_paper_r4.summary.tsv`):**
- LongOrfs ORFs, IDs, order and proteins are identical in all 5 datasets. The only difference is that Perl keeps soft-masked lowercase in the `.cds` output.
- The hexamer model and all 6-frame scores of every ORF are identical in all 5.
- The pre-refinement selected ORF sets are identical in all 5.
- Final ORFs are identical at the stop-codon level: 0 Perl-only and 0 Python-only ORFs in every dataset.
- The only remaining differences are start codons chosen by PWM refinement:

  | Dataset | ORFs with a different start |
  |---|---|
  | Trinity | 12 / 679 |
  | PASA | 53 / 792 |
  | StringTie | 97 / 3037 |
  | Cufflinks | 4 / 80 |
  | SuperTranscripts | 0 / 117 |

**Before the fixes (v6.0.0 baseline, `data/regression/baseline_v6.0.0.summary.tsv`):**
- StringTie had 22 Perl-only and 30 Python-only ORFs.
- Trinity had 1 and 4.
- Markov scores differed for nearly every ORF.

**Runtime (Python vs Perl):** Python is about 2.7× faster on these small sets. For example, StringTie takes 47 s in Python vs 127 s in Perl.

## Start refinement is seed-sensitive (`analyses/start_refinement_stability/`)
PyTD was rerun with seeds 1–5 for the PWM training RNG. Starts that differ from seed 1:

| Dataset | ORFs | Differing starts (seeds 2–5) |
|---|---|---|
| Trinity | 679 | 14–26 |
| PASA | 792 | 29–61 |
| StringTie | 3037 | 47–144 |

The best-AUC (upstream, downstream) window swings widely, e.g. PASA (15,2) → (20,2) → (3,7) → (20,9) → (7,2).

**Conclusion:** the remaining Perl/Python start differences are within seed noise. They come from the random 75/25 splits plus noise depletion, and the near-tied AUCs across windows.

**Candidate improvement (needs a decision):** make start-PWM training deterministic and stable. Options:
- Average AUC over many folds.
- Use a fixed window.
- Ensemble over windows.

Evaluate the options against the benchmark truth sets.

## Long-ORF threshold simulation (`analyses/long_orf_threshold/`)
- The original simulation script was not found in any repo or in ~/GITHUB/HAASUTIL.
- It was regenerated with `simulate_random_orf_lengths.py`. The model is LongOrfs ORFs (partials allowed, both strands, ≥300 nt) in i.i.d. random sequence with complement-symmetric composition.
- 5 kb sequences reproduce the 2017 table (`table_2017.tsv`):

  | GC% | 2017 | Regenerated |
  |---|---|---|
  | 60 | 927 | 927 |
  | 65 | 1086 | 1083 |
  | 75 | 1743 | 1746 |
  | 80 | 2423 | 2436 |

  Agreement is within about 3% at ≥50% GC. 10 kb sequences give the same values (insensitive to length).
- At ≤45% GC the 2017 values are 2–10% lower. For example, at 25% GC: 465 (2017) vs 519 (n=1,718 ORFs). The 2017 q0.999 ≈ q0.9999 pattern at low GC points to a small sample. The new table is in `regenerated_thresholds.tsv`.
- Mouse-length random sequences (as in `mirror_random_fasta.py`) give somewhat lower values, so the threshold depends weakly on the transcript length distribution.
